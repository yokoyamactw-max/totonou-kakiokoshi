# サブエージェントに渡すプロンプトの型

要約と整形は Sonnet のサブエージェントに任せる（`Agent(model: "sonnet", run_in_background: true)`）。
同時に動かすのは3体まで。どの型も冒頭に「あなたが作業者本人です。再委任（Agentツール使用）は禁止。」を入れる。
`{…}` は埋めてから渡す。

## 目次
1. 要約：講義・セミナー型
2. 要約：会議型（ToDo 抽出あり）
3. 要約＋整形：短尺（20分以下）の一体型
4. 整形：チャンク型

---

## 1. 要約：講義・セミナー型

```
あなたが作業者本人です。再委任（Agentツール使用）は禁止。

{教材名}（約{長さ}、話者：{講師名}）の自動文字起こしを読み、個人視聴用の要約をHTML断片として書き出してください。{利用条件：例「主催者の許可済み・ユーザー個人の学習メモ用途」}。

- 入力：{workdir}/transcript.txt（`[分:秒] 発言` 形式。Readのoffset/limitで最後まで全部読むこと。途中で打ち切らない）
- 出力：{workdir}/summary.html（Writeで作成。<html>や<body>は付けず断片だけ）

## 注意
- Whisperの自動認識なので誤変換がある。文脈から意味を取る
- 要約は自分の言葉で書く。原文の長い引用はしない（引用するなら1か所15字程度まで）
- 数値・具体例・価格・期限は話された範囲だけ。推測で補わない。不明な点は「（聞き取り不明瞭）」
- 同じ言葉が延々続く箇所は音声が不明瞭な区間なので無視してよい
{休憩などの無音区間があれば：例「1:38〜1:45は休憩で無音」}
{販売案内がありそうなら：「価格・支払い方法・特典・申込期限・返金条件は聞き取れた範囲で正確に」}

## summary.html の形
1. <h2>3行でいうと</h2> 結論3行（<ul>）
2. <h2>章立て</h2> 時間帯ごとの区切りを <ol> で8〜15項目。時刻は「時:分」表記（分を60で割る。例 [97:10] → 1:37）。各項目に1〜2文
3. <h2>重要ポイント</h2> 実践できる学びを10〜20個。<ul>で太字見出し＋1〜3文＋（該当時刻 時:分）
4. {内容に応じて追加：受講生事例（個人名は伏せて「事例1」）／販売案内／宿題・次回案内 など}

日本語、常体・体言止めでよい、絵文字禁止。
完了報告は「summary.html を書いた」「最終行まで読んだか」「不明瞭だった箇所」だけを短く。
```

## 2. 要約：会議型（ToDo 抽出あり）

```
あなたが作業者本人です。再委任（Agentツール使用）は禁止。

ユーザー自身のミーティング（{日時}、約{長さ}、話題：{わかる範囲で}）の自動文字起こしを読み、本人用の議事まとめを作ってください。ローカル保存のみで公開しません。

- 入力：{workdir}/transcript.txt（最後まで全部読むこと）
- 出力：{workdir}/summary.html（Writeで作成、断片のみ）

## summary.html の形
1. <h2>このミーティングの要点</h2> 何のための打ち合わせで何が決まったかを3〜5行（<ul>）
2. <h2>話の流れ</h2> <ol> で10〜18項目。太字の見出し＋1〜2文＋（時刻 時:分）
3. <h2>決まったこと・分かったこと</h2> 事実ベースの箇条書き。数字・ツール名・API名は正確に
4. <h2>次にやること（ToDo）</h2> 最重要。「**動詞で始まる具体的な行動** — 背景1文（担当が分かれば明記）（該当時刻）」を12個以内。会話中の宿題・約束・「やっておきます」を拾う。推測で作らない
5. <h2>保留・未決</h2> 結論が出ていない論点（なければ「なし」）
6. <h2>用語メモ</h2> 固有名詞・ツール名を1行ずつ

確信が持てない固有名詞は末尾に（？）。聞き取れない箇所は「（聞き取り不明瞭）」。絵文字禁止。
完了報告は「summary.html を書いた」「最終行まで読んだか」「ToDo件数」「不明瞭だった箇所」だけ。
```

## 3. 要約＋整形：短尺（20分以下）の一体型

短い素材はサブエージェント1体で要約と整形を両方やらせる（起動回数を減らすため）。

```
あなたが作業者本人です。再委任（Agentツール使用）は禁止。

{素材名}（約{長さ}、話者：{名前}）について、要約と書き起こし整形の2つを作ってください。{利用条件}。

フォルダ：{workdir}/

## 仕事1：要約 summary.html（断片のみ）
入力 transcript.txt（最後まで読む）
1. <h2>この{動画/音声}について</h2> 何をテーマに話しているか2〜3文（<p>）
2. <h2>3行でいうと</h2>（<ul>）
3. <h2>話の流れ</h2> <ol> で4〜8項目（「分:秒」表記）
4. <h2>すぐ使えるポイント</h2> 5〜10個。太字見出し＋1〜3文＋（該当時刻）

## 仕事2：整形 clean/out_1.json
（下の「4. 整形」の整え方・自己チェックと同じ）

完了報告は「summary.html と out_1.json を書いた・ブロック数N・キー漏れなし・ですよX回・っていうY回」の1行だけ。
```

## 4. 整形：チャンク型

```
あなたが作業者本人です。再委任（Agentツール使用）は禁止。

{素材の説明}の自動文字起こしを、読みやすい文章に整えてください。{利用条件}。

フォルダ：{workdir}/clean/
- 入力：in_{N}.json（[{"t":秒, "text":"生の書き起こし"}...]）。Readで全体を読むこと
- 出力：out_{N}.json（Writeで作成）。形式は {"<t>": ["段落1", "段落2", ...]}。入力の全ブロックの t を漏れなくキーにする（textが空なら空配列）

## 整え方
- フィラー削除：「えー」「あのー」「まあ」「なんか」「ちょっと」の口癖的用法、「はい」「そう」の相づち連発、言い直し・どもり
- 句読点を補い、話題の切れ目で段落分け（1段落2〜4文）
- 口調は読み物として自然なです・ます調に：「〜なんですよ」「〜ですよね」は強調以外は言い切る／「〜っていう」「〜って」は「〜という」「〜は」に／「結局」「めっちゃ」「マジで」などの口癖は1段落1回まで／倒置は直す
- {複数人の会話なら：話者が切り替わったと読み取れるところは段落を分け、相手の発言の冒頭に「――」を付ける（誰かは断定しない）}
- 内容の追加・削除・要約はしない。数字・例・手順・価格・期限・冗談はすべて残す
- 明らかな誤変換は文脈から直す。確信が持てない固有名詞は元の表記のまま末尾に（？）
- 数字が不自然で意味が取れないときは、推測で別の数字や「大きな金額」に置き換えない。元の表記のまま（？）を付ける。同じ桁が延々と続く機械エラーはその部分だけ「（数字が不明瞭）」
- 壊れて同じ語句が続く箇所は「（音声が不明瞭な区間）」

## 自己チェック（Write後に必ず）
1.「ですよ」「っていう」がそれぞれ20回以下（会話なら30回以下）か
2. 全キーがそろっているか
3. 同じ語句や数字が5回以上連続していないか

完了報告は「out_{N}.json を書いた・ブロック数N・キー漏れなし・ですよX回・っていうY回・繰り返し異常なし」の1行だけ。本文は貼らない。中間ファイルは作らない。
```
