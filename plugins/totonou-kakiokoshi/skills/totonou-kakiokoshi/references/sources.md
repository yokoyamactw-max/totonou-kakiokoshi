# 素材の取り込み方（入口別）

## UTAGE のページ（utage-system.com/p/...）
動画はページ内の `<video>` か `data-hls` 属性に HLS（`video.m3u8`／音声だけなら `audio.m3u8`）で入っている。
Browser ペインでページを開き、次を実行して URL を拾う。

```js
[...new Set((document.documentElement.innerHTML.match(/https?:\/\/[^"'\s\\]+\.m3u8/g)||[]))]
```

見出しと突き合わせて、何本あるか・どれが何かを先に一覧にしてユーザーに見せる（特典ページは動画と音声が混在し、PDF資料も並ぶ）。
取り込みは `fetch.py --hls <URL>`。長さの見積もりは m3u8 の `#EXTINF` 合計で出せる。

## Zoom のクラウド録画（zoom.us/rec/share/... ・ /rec/play/...）
- 動画URLはログイン中のブラウザでしか通らない（外から curl すると 403）
- ブラウザ内の fetch は通るが、https のページから http://127.0.0.1 への送信はブラウザに止められるので、ブラウザ経由の橋渡しはできない
- 録画ページに文字起こしが無ければ（Zoom側の文字起こし設定がオフ）、音声から起こすしかない

→ 最初からユーザーに次のどちらかをお願いするのが最短：
  1. 「ダウンロード」から保存して `~/Downloads` に置いてもらう → `fetch.py --file`
  2. Google Drive に上げて、共有を「リンクを知っている全員」にしてもらう → `fetch.py --drive <ID>`
  取り込み後は共有設定を元に戻すよう伝える。

## Google Drive
- 連携中のGoogleアカウントからは、共有されていないファイルは「見つからない」になる。フォルダだけ共有されていても中身は見えないことがある
- 「リンクを知っている全員」にしてもらえば `fetch.py --drive <ファイルID>` で取れる（大容量のウイルススキャン確認画面も自動で通す）
- **途中で切れることがある**。fetch.py は Content-Length と突き合わせ、足りなければ `-C -` で続きを取り直す。それでも足りなければ止まるので、そのまま完了扱いにしない

## Loom・YouTube・Vimeo など（ページURL）
`fetch.py --url <ページURL>`。中身は yt-dlp なので、yt-dlp が対応しているサイトならそのまま取れる。
- 取り込む前に `yt-dlp --no-warnings --print "%(title)s | %(duration)s | %(uploader)s" <URL>` で題名・長さ・投稿者を確認する。投稿者と画面の中身から「誰の素材か」を判断する（Loom に上がっていても、中身は他人のウェビナー録画ということがある）
- Loom は映像と音声が別々に配信されていて、両方を落としてから1本にまとめる。1時間半で600MB前後、10分以上かかることがある
- ログインが必要なページ・限定公開の設定によっては取れない。そのときは動画を保存してもらい `--file` で渡す

## パソコン内のファイル
`fetch.py --file <パス>`。コピーせずシンボリックリンクを張る。

## 一部区間だけ（例：23:00〜25:40）
`fetch.py ... --start 1380 --end 1540`。以降のスクリプトはすべてこの区間だけを処理し、時刻は元動画の時刻で表示される。
