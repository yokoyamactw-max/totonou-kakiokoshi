# ととのう書き起こし（totonou-kakiokoshi）

動画1本を「あとで読み返せる資料」に変える。
スクリプトでできること（取り込み・スクショ・区切り・組み立て・検証）はコードに任せ、AIには要約と文章の整形だけを任せる。人の手で毎回判断すると抜けが出るところほど、スクリプト側で機械的に確認する。

スクリプトはこのスキルのフォルダ（読み込み時に表示される Base directory）の `scripts/` にある。以下ではそのパスを `$S` と書く。コマンドを実行するときは `$S` を実際のパスに置き換える。

**Python の呼び方**：Mac は `python3`。Windows は `python`（`python3` と打つと Microsoft Store の案内が開くことがある）。以下の `python3` は Windows では `python` に読み替える。パスに日本語や空白が入るときは `"..."` で囲む。

文字起こしはパソコンの中で動く音声認識を使うので無料。要約と整形は Claude の利用枠を使う（外部APIの別料金はかからない）。

| パソコン | 文字起こしエンジン | 1時間半の動画の目安 |
|---|---|---|
| Apple シリコン（M1以降）の Mac | mlx-whisper（速い） | 3〜10分 |
| Windows・Intel Mac | faster-whisper（CPU） | 30分〜1時間半（CPU の性能しだい） |

`transcribe.py` が自動で選ぶ。どちらも同じモデル（large-v3-turbo）なので、仕上がりの質は変わらない。

## 0. 始める前に確認すること

- **環境**。最初に `python3 $S/check_env.py` を実行する。NG なら、表示された入れ方をユーザーに伝える
  - 「文字起こしエンジン faster-whisper」が足りないときは、ユーザーの了解を取ってから `python3 $S/check_env.py --setup` を実行してよい（専用環境を作り、モデル約1.6GBを準備する。10〜20分かかるので `run_in_background` で回す）
  - ffmpeg・yt-dlp・Python 本体の導入（brew・winget）は、ユーザーの了解を取ってから実行する。Windows で winget で入れた直後は、Claude Code を開き直さないとコマンドが見つからない
- **誰の素材か**。他人の講座・有料教材なら、ユーザーが個人で視聴する範囲の許可を得ているか確認する。できあがったHTMLは教材の全文とスライドを含むので、ネットに公開したり共有リンクを作ったりしない。公開を頼まれたら、主催者の許可範囲を超えることを伝え、本人だけが見られる置き場所（本人のDrive・パソコン内）を提案する
- **範囲**。全編か、一部区間か。ページに複数本ある場合は、本数と長さを一覧にしてから、どれをやるか・1本1ファイルかを聞く
- **種類**。講義・セミナー／会議（ToDoが要る）／音声だけ、のどれか。要約の型が変わる
- **出力先**。ユーザーの指定があればそこへ。Obsidian を使っている人なら、保管庫（Vault）の中に置くと目次ノートで探しやすくなる（「4. 目次ノート」）ので、置き場所を聞く。指定がなければ `~/Documents/ととのう書き起こし/`（なければ作る）

## 1. 取り込み

作業フォルダは Mac なら `~/Movies/totonou-kakiokoshi/<日付_短い名前>/`、Windows なら `~/Videos/totonou-kakiokoshi/<日付_短い名前>/`（動画は大きいので、出力先とは分ける）。

```bash
python3 $S/fetch.py <workdir> --file <パス>        # パソコン内
python3 $S/fetch.py <workdir> --url  <ページURL>   # Loom・YouTube・Vimeo など（yt-dlp）
python3 $S/fetch.py <workdir> --hls  <m3u8のURL>   # UTAGE など
python3 $S/fetch.py <workdir> --drive <ファイルID>  # Drive（リンク共有が必要）
# 一部区間だけなら --start 秒 --end 秒 を足す
```

- URLを渡されたら、まず `yt-dlp --no-warnings --print "%(title)s | %(duration)s | %(uploader)s" <URL>` で題名・長さ・投稿者を確かめ、ユーザーに伝えてから取り込む。1時間を超える動画は取り込みに10分以上かかることがあるので、`run_in_background` で回す
- 入口ごとの注意（UTAGEでURLを拾う方法、Zoomは外から取れない件、Driveの共有）は `references/sources.md` を読む
- fetch.py が「途中で切れています」「音声トラックが短い」と出したら、そこで止めて原因を確かめる。表示上の長さと中身が合わないまま進めると、末尾をまるごと落とす

## 2. 文字起こしとスクショ（同時に回してよい）

```bash
python3 $S/transcribe.py <workdir>                 # エンジンは自動で選ぶ（無料・ローカル）
python3 $S/shots.py <workdir> --mode fine          # 画面がない音声素材では不要
```

- faster-whisper（Windows・Intel Mac）は時間がかかるので、10分を超える素材は `run_in_background` で回す。5分ぶん進むごとに「進捗 15/90分（残り目安 40分）」のように出るので、ユーザーに残り時間を伝える。その間にスクショと区切りを進めてよい
- スクショのモード：講義・スライドは `fine`（一瞬の画面も拾う）、画面共有の打ち合わせは `key`（要所だけ）、プロジェクターをカメラで撮った映像は `coarse`。`fine` で「目安上限」を超えたら中身を数枚見て、モードを変えて撮り直す
- Zoom などの録画でスライドが画面の一部にしか映っていなくても、動きの多い部分（顔映像など）を自動で除いて文字だけのスライド切り替えも拾う（「補助検出で追加 N 枚」と表示される）
- 撮れたスクショを数枚開いて、スライドの切り替わりが抜けていないかを目で確かめる。ここで抜けに気づかないと、あとで整形をやり直すことになる
- transcribe.py が「ループ区間」を出したら、表示された `--redo 開始秒 終了秒` で、その部分だけ精度の高いモデル（large-v3）で聞き直す。相づちや笑い声しかない区間なら「音声が不明瞭な区間」として残せばよい。講義の中身が入っていれば差し替える
- `2,000,000` のような桁のおかしい数字も、その前後だけ聞き直す。「2、3000万」の聞き崩れであることが多い

```bash
python3 $S/transcribe.py <workdir> --redo 3336 3378   # 55:36〜56:18 を聞き直して表示（秒で指定）
```

## 3. 区切りと要約・整形

```bash
python3 $S/prep.py <workdir>          # clean/in_N.json を作る（1チャンク≒1.8万字）
```

スクショを撮り直したら、必ず prep.py からやり直す（区切りはスクショの時刻で決まるので、整形済みの文章とずれる）。

要約とチャンクごとの整形をサブエージェントに任せる（使えるなら `model: "sonnet"`・`run_in_background: true`）。プロンプトの型は `references/prompts.md`（講義型／会議型／短尺一体型／整形型）。サブエージェントが使えない環境では、同じプロンプトの内容を自分で順に実行する。

- 同時に動かすのは3体まで。1体終わるごとに次を流す
- 20分以下の素材は、要約と整形を1体にまとめる
- 1体終わるごとに、キーの抜け・文字数の比率・数字を確認する（verify.py がやる内容と同じ。途中で見ておくと手戻りが減る）。比率が0.7を切ったら、末尾の話と数字が残っているかを実際に見比べる
- 要約が「聞き取り不明瞭」とした箇所は、元の transcript.txt と、その時刻のスクショ（スライドに正しい表記が出ていることが多い）で確かめて直す

## 4. 組み立てと検証

```bash
python3 $S/build.py <workdir> "<出力.html>" "<タイトル>" "<メタ行>"
python3 $S/verify.py <workdir> "<出力.html>"
```

- ファイル名は `YYYY-MM-DD_内容がわかる名前_書き起こし.html`。ページ上の題名と中身が違ったら、中身に合わせて名付け、タイトルに元の表記も併記する
- メタ行には、長さ・自動文字起こしである旨・個人用である旨、それに注意点（音声が不明瞭な区間、画面が読みにくい映像など）を入れる
- verify.py が NG を出したら直してから完了とする。OK が出ても、ブラウザで開いて表示を確かめる（Mac は `open "<出力.html>"`、Windows は `start "" "<出力.html>"`）
- スクショはHTMLに埋め込むので、1時間半の講義で30〜40MBになる。メールで送るには大きいことを伝える

### 目次ノート（Obsidian を使っている人だけ・任意）

出力先が Obsidian の保管庫の中なら、作るかどうかを聞き、希望があれば作る。

```bash
python3 $S/catalog.py "<出力.html>" --kind 講座 --series "<シリーズ名>" --speaker "<講師・主催>" --owner 他人 --url "<元URL>" --tags "<タグ1>,<タグ2>"
```

- HTMLと同じフォルダに同名の `.md` ができる。日付・種類・シリーズ・講師などの属性、HTMLを開くリンク、要約、本文テキストが入り、Obsidian の検索で中身まで探せるようになる（Obsidian は HTML の中身を検索しないため）
- 自分の会議は `--kind 会議 --owner 自分 --speaker 自分`。音声だけの素材は `--kind 音声`
- 作り直しても「## メモ」欄に書いた内容は残る
- 一覧表がほしい人には、`templates/kakiokoshi-ichiran.base` を保管庫の好きな場所に `書き起こし一覧.base` という名前でコピーする（Obsidian のコア機能「Bases」で、タグ「書き起こし」の付いた目次ノートが新しい順・シリーズ別に並ぶ）

- 保存先、ブロック数、スクショ枚数、ファイルサイズ
- 要約で「聞き取り不明瞭」になった箇所のうち、お金や判断に関わるもの（価格・期限・条件）は時刻付きで挙げ、動画で確かめるよう伝える

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| check_env.py が NG | 表示された入れ方を実行してもらう。mlx_whisper・winget で入れたものは、ターミナルや Claude Code を開き直さないと見つからないことがある |
| Windows で `python3` と打つと Microsoft Store が開く | `python` で呼ぶ。`python` も見つからなければ `py` で呼ぶ |
| `--setup` が途中で止まる | 回線の問題が多い。もう一度実行すれば続きから進む。会社のネットワークで Hugging Face（huggingface.co）が止められていることもある |
| 文字起こしがとても遅い | Windows・Intel Mac は CPU で動くため。他のアプリを閉じる。一部区間だけ先に試す（--start/--end） |
| HTMLの文章が整形前のまま | build.py が読むのは `out_数字.json` だけ。控えファイル名を `out_2_pass1.json` 以外にしていないか |
| 整形文が表示されないブロックがある | prep.py の後にスクショを撮り直した。prep.py からやり直す |
| 冒頭に空のブロックが並ぶ | meta.json の start が0のまま一部区間を処理している。fetch.py に --start/--end を渡し直す |
| スクショが数百〜数千枚 | カーソル移動や投影のムラを拾っている。`--mode key` か `coarse` |
| 文字スライドの切り替えが抜ける | 補助検出が動いていない（画面の7割以上が動き続ける映像）。`--mode fine` で撮り直し、それでも抜ける区間はその時刻の画面を ffmpeg で1枚ずつ切り出して shots/ に足し、prep.py からやり直す |
| 文字起こしが途中で終わる | 素材が途中切れ。fetch.py の警告と、元ファイルの実サイズを確認して取り直す |
| `--url` で取れない | ログインが必要なページ。ユーザーに動画を保存してもらい `--file` で渡す |
